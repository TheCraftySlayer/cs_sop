How the AI Operations SOPs fit together

One system, six SOPs

The AI Operations SOPs are organized into two lanes — detection (daily, weekly, monthly checks plus a reference baseline) feeds action (change management for fixes, incident response for emergencies). Most of the time the work flows from top to bottom; when something is critical, it skips straight to incident response.

Detection · routine monitoring
AIO01

Daily Check

Daily · ~10 min

Triage Missing Content, scan latest prompts, check risk monitoring. Catches problems within one business day.
AIO02

Weekly Review

Mon · ~30 min

Sample 20 conversations, tag them, run the Spanish canary, export the backup.
AIO04

Monthly Metrics

1st of month · ~30 min

Compile metrics from three CustomGPT tabs. Update tracker. Apply monthly thresholds for governance.
AIO06

Baseline Reference

As needed · annual

Authoritative "as configured" snapshot. The source of truth that reviews check against and changes update.
Action · response to what detection found
AIO03

Change Management

Planned · per change

The four-section playbook for safely changing A.C.E. — Persona, KB file, Actions, Configuration. Every planned change flows through here.
AIO05

Incident Response

Emergency · same-day

Four classes of incident — wrong answer, agent down, PII disclosure, abusive user. Severity order is C → B → A → D.

How to read this

Detection finds something — wrong answer, drift, threshold breach. Action resolves it.

Most of the time problems flow from detection (AIO01/02/04) into change management (AIO03). When something is critical — PII, threats, agent down — it skips straight to incident response (AIO05). The baseline (AIO06) is the reference frame: detection compares against it, and every change updates it.

Detection → Action

Wrong answer in AIO01/02 → fix per AIO03 (KB file or Persona).

Threshold breach in AIO04 → adjust per AIO03 (Configuration), or plan upsize.

PII / threat / outage in any check → AIO05 first, AIO03 after.

The baseline loop

Every AIO03 change updates the AIO06 baseline. Reviews use the baseline to spot unauthorized drift. Without a current baseline, change history is unverifiable.
